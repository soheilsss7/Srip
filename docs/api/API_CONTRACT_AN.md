# PHASE AN — API Contract

Canonical API contract for `/api/v1`.

## Required contract surface

Every endpoint must be represented in generated OpenAPI/Swagger and must document:

- Authentication/security requirement (Bearer/OIDC where applicable).
- Standard error codes and `{code,message,requestId,details?}` error shape.
- Request/response examples.
- Pagination for collection endpoints (`page`, `cursor`, `limit`, `sort`, `order`).
- Resource-specific filters when supported by the endpoint.
- `X-Request-Id` and `X-Correlation-Id` tracing headers.
- `Idempotency-Key` on authenticated retry-sensitive mutations.
- Inbound signed webhook contract separately from Bearer-authenticated APIs.

## Authentication

Protected operations use `Authorization: Bearer <access-token>`. Public authentication bootstrap routes and health routes are explicitly marked public. Webhooks use provider signature verification instead of Bearer authentication.

## Error contract

| HTTP | Canonical code | Meaning |
|---|---|---|
| 400 | `VALIDATION_ERROR` | malformed/invalid request |
| 401 | `UNAUTHENTICATED` | missing/invalid authentication |
| 403 | `FORBIDDEN` | authorization denied |
| 404 | `NOT_FOUND` | missing/hidden resource |
| 409 | `CONFLICT` | state/duplicate/idempotency conflict |
| 422 | `UNPROCESSABLE_ENTITY` | semantically invalid request |
| 429 | `RATE_LIMITED` | rate limit exceeded |
| 500 | `INTERNAL_ERROR` | unexpected server error |
| 503 | `SERVICE_UNAVAILABLE` | dependency unavailable |

Example:

```json
{"code":"FORBIDDEN","message":"Authenticated principal is not authorized for the resource.","requestId":"018f3f2d-7e72-7b11-8d45-9f0b7d7f2b1a"}
```

## Pagination

Collection endpoints use bounded pagination. `limit` is server-capped at 200. Cursor pagination is represented by `nextCursor`; `page` and `cursor` are alternative pagination modes.

Example:

```json
{"items":[],"nextCursor":null,"total":0}
```

## Filters

Filters are resource-specific and are documented from the endpoint's actual query contract; the API does not advertise synthetic filter parameters that handlers do not implement. Existing filters include organization/scope, status, type, query/search text and date ranges where supported.

## Webhooks

`POST /api/v1/integrations/webhooks/{provider}` is documented as an OpenAPI 3.1 webhook contract. It is not Bearer-authenticated. The raw HTTP body is signature-verified first, timestamp/replay protection is applied, the event is persisted idempotently, and only then is it normalized into a Domain Event.

Required/optional headers include `x-webhook-signature`, `x-webhook-timestamp`, `x-event-id`, and `x-event-type`.

## Source of truth

Runtime OpenAPI is generated by Nest Swagger at `/docs` and `/docs-json`. `main.ts` hardens the generated document at startup and fails startup if required canonical paths are absent.
