## ۰) بازبینی: چرا «بازی» غلط است و چه چیزی درست است

۱. **«بازی» اسم یک سرگرمی است، نه یک روش تحلیل.** کاربر هرگز «بازی» نخواست؛ خواستار **چیدمانِ تحلیل بر اساس نظریه بازی‌ها** بود. نام‌گذاری ماژول به `game` کل مفهوم را وارونه می‌کرد.
۲. **هیچ اثری از آن «بازی» در ریپو نیست** (نه سورس، نه `game.html`، نه کامیت) چون سشن قبلی قبل از push قطع شد. پس «بازبینی» یعنی: **طراحی درست از صفر**، نه ترمیم چیزی که وجود ندارد.
۳. **اصلاح ساختاری:** نام فارسی «تحلیل راهبردی»، روت `/strategy`، مجوزهای `strategy.read/write`، محرک‌های `STRATEGY_*`، مقاله دانشی `kb-strategy`. کلمهٔ «بازی» فقط داخل اصطلاح علمی «نظریه بازی‌ها» می‌آید و بس.
۴. **اصل دقت:** هر ادعای نظری فقط در دامنهٔ اعتبارش پیاده می‌شود (مثلاً تعادل نش خالص/مختلط فقط برای بازی ۲بازیکنه؛ برای Nبازیکنه فقط شبیه‌سازی تکراری + آمار، بدون ادعای تعادل).

---

## ۱) تعریف ماژول

«تحلیل راهبردی» به هر شرکت می‌گوید **در برابر رقبا/طرف‌ها چه راهبردی بگیرد**:

> **بازیگران** (از سازمان‌های سامانه یا دادهٔ واردشده از پلتفرم دیگر) + **راهبردها** + **عایدی‌ها**
> ← **تعادل‌ها** (نش خالص/مختلط، SPE در بازی ترتیبی)
> ← **شبیه‌سازی** تعامل تکراری با قواعد رفتاری
> ← **پیش‌بینی** حرکت بعدی رقیب و **توصیهٔ واکنش بهینه** (بهترین پاسخ)
> ← **خروجی** (بریف یک‌صفحه‌ای، JSON/CSV/Excel، اقدام و گردش‌کار)

## ۲) مبانی نظری (دامنهٔ دقیق پیاده‌سازی)

| # | مفهوم | تعریف عملیاتی در سامانه | دامنه اعتبار |
|---|---|---|---|
| ۱ | بازی فرم‌نرمال ۲بازیکنه | ماتریس عایدی `A (m×n)` برای «خود» و `B (m×n)` برای رقیب؛ راهبردها سطر/ستون | ۲ بازیکن، m و n دلخواه |
| ۲ | بهترین پاسخ | سطری/ستونی با بیشترین عایدی در برابر راهبرد ثابت طرف مقابل (با تلرانس تساوی `1e-9`) | ۲بازیکنه |
| ۳ | تعادل نش خالص | خانه‌ای که هر دو عایدی، بهترین پاسخ متقابل‌اند (نشانه‌گذاری هر دو) | ۲بازیکنه |
| ۴ | تعادل نش مختلط ۲×۲ | حل تحلیلی: `q*=(a11−a21)/(a11−a12−a21+a22)` برای بی‌تفاوتی خود و قرینه برای رقیب؛ فقط اگر در `[0,1]` باشد | دقیقاً ۲×۲، بدون نش خالص |
| ۵ | حذف غلبه اکید تکراری | حذف سطر/ستون اکیداً مغلوب تا تثبیت؛ گزارش مراحل | ۲بازیکنه |
| ۶ | بازی ترتیبی اطلاعات‌کامل | درخت متناهی (گره تصمیم + شاخه + عایدی برگ)؛ **استقرای پسرو** ← مسیر تعادل کامل زیربازی (SPE) | درخت متناهی، بدون شانس |
| ۷ | بازی تکراری متناهی/نامتناهی | شبیه‌سازی N دور با قواعد: همیشه‌همکاری، همیشه‌نقض، تلافی‌مثل (TFT)، ماشه‌ای (Grim)، بهترین‌پاسخ، تصادفی بذردار | هر تعداد بازیکن (۲+ دقیق، بیشتر فقط آماری) |
| ۸ | شرط پایداری همکاری | در نظم عایدی `T>R>P>S`: `δ ≥ (T−R)/(T−P)`؛ اگر نظم برقرار نباشد «قابل محاسبه نیست» (نه عدد غلط) | ۲بازیکنه متقارن‌سان |
| ۹ | پیش‌بینی حرکت بعدی | توزیع فراوانی تاریخچه (بازی تخیلی) + تطبیق الگوی TFT/Grim؛ توصیه = بهترین پاسخ به توزیع پیش‌بینی‌شده + عایدی موردانتظار | ۲بازیکنه |
| ۱۰ | قالب‌های کلاسیک | معمای زندانی، شکار گوزن، جوجه (تقابل)، هماهنگی، سکهٔ مشابه، بازدارندگی ورود (ترتیبی)، جنگ قیمت (تکراری) — با عایدی‌های متعارف و روایت کسب‌وکاری فارسی | نمایشی/آموزشی + نقطه شروع سناریو |

**قواعد دقت:** بدون `Math.random` در موتور (PRNG بذردار mulberry32)؛ همهٔ محاسبات قطعی و تکرارپذیر؛ اعداد فارسی در UI؛ هیچ رشتهٔ لاتین در رابط کاربر (به‌جز JSON/CSV/Excel که سابقه دارد).

## ۴) معماری فنی

- **موتور** (`apps/web-ux/scripts/mock-api.mjs`، بخش جدید `STRATEGY`): توابع خالص + روت‌های `/strategy/*` + سید دمو + بازتولید در `resetDbInPlace` + تعبیه خودکار در `sw.js` via `make-demo-sw.mjs`.
- **رابط کاربر** (`apps/web-ux/app/strategy/page.tsx`، `'use client'`): شش تب — نمای کلی / رقبا / اتصال داده / شبیه‌سازی / پیش‌بینی و واکنش / خروجی. ناوبری سایدبار + صفحه راهنما + مقاله `kb-strategy`.
- **مجوزها:** `strategy.read` (در `R_READ`) و `strategy.write` (در `R_WRITE`) + گروه کاتالوگ `Strategy`.
- **گردش‌کار:** `STRATEGY_SCENARIO_CREATED`، `STRATEGY_SIMULATED`، `STRATEGY_PREDICTED`، `STRATEGY_IMPORT_COMPLETED` (تعریف خودکار + اقدام/اعلان واقعی مثل عموم‌ها).
- **خروجی:** JSON (apiBlob) / CSV (utf-8) / Excel (قالب HTML-XLS راست‌به‌چپ مثل عموم‌ها).

## ۶) قرارداد API (خلاصه؛ جزئیات در کد)

- `GET /strategy/archetypes` — قالب‌های کلاسیک
- `GET/POST /strategy/scenarios` + `GET/PUT/DELETE /strategy/scenarios/:id` — سناریوها (فرم‌نرمال ۲بازیکنه یا ترتیبی)
- `GET /strategy/scenarios/:id/analysis` — بهترین‌پاسخ‌ها، نش خالص، نش مختلط (۲×۲)، مراحل حذف غلبه، SPE (ترتیبی)، شرط δ
- `POST /strategy/scenarios/:id/simulate` — `{rounds, delta, rules:{self,rival}, seed}` ← تاریخچه دورها + عایدی انباشته + نرخ همکاری
- `POST /strategy/scenarios/:id/predict` — `{history?}` ← توزیع پیش‌بینی + بهترین پاسخ + عایدی موردانتظار
- `POST /strategy/imports/validate` و `POST /strategy/imports` — اعتبارسنجی و ثبت ورود (`{format:'json'|'csv', payload}`)
- `GET /strategy/imports/template?format=` — قالب دانلودی
- `GET /strategy/export?format=json|csv|xls` — خروجی
- `GET /strategy/brief/:id` — بریف یک‌صفحه‌ای

**اسکیمای ورود JSON (نسخه ۱):** `{version:1, players:[{key,name}], strategies:{self:[...],rival:[...]}, payoffs:{self:[[..]],rival:[[..]]}, rounds?:[{round,self,rival,paySelf,payRival}], meta?}` — اعتبارسنجی: مستطیلی‌بودن، تطبیق ابعاد، عددی‌بودن، ارجاع‌های معتبر.
**CSV:** سرستون `round,self,rival,paySelf,payRival` (برای تاریخچه) یا `strategy_self,strategy_rival,pay_self,pay_rival` (برای ماتریس، با `kind=` در کوئری).
