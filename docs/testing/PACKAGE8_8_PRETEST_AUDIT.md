# Package 8.8 — Pre-Test Hardening Audit

Baseline: Package 8.7
Scope: repeat audit of Data Quality, Duplicate Detection, Import, Storage Readiness, Sensitive Data Sanitization, CI/Governance, Monitoring, Backup/Restore contract, DB latency/slow queries, Network/Search/Reporting EXPLAIN + benchmark tooling, connection pool verification, and cache invalidation.

## Findings fixed

1. **Network query completeness** — network graph organization search was applied after fetching only the first cursor page. The query is now pushed into the DB `where` clause so later matching organizations are not missed.
2. **Data Quality duplicate detection** — duplicate grouping is now case/whitespace normalized in PostgreSQL and returns bounded candidate IDs directly, avoiding a second broad candidate fetch. `DATA_QUALITY_MAX_IDS` parsing is resilient to invalid environment values.
3. **EXPLAIN benchmark correctness** — the previous shell `psql -c "..."` form stripped PostgreSQL identifier quotes. The benchmark now uses heredoc SQL, so Network/Search/Reporting EXPLAIN commands are actually executable.
4. **Cache verification correctness** — the runtime check previously manually deleted Redis keys, proving Redis connectivity but not the application's canonical invalidation path. It now invokes `PerformanceCacheService.invalidatePrefix()` and verifies the resulting Redis state.
5. **Pre-test gate** — the static gate now requires the canonical cache runtime probe and keeps unsafe raw SQL checks.
