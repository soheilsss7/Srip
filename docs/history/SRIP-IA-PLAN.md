## ۱) خلاصهٔ وضعیت (یک نگاه)

سامانه از نظر **قابلیت** بسیار غنی است (۸۲ مسیر، ۱۱۵ نقطهٔ اتصال API واقعی در Mock) اما از نظر **معماری اطلاعات (IA)** به‌هم‌ریخته است. نتیجه:

- منو شش «خانهٔ کاری» + یک بخش ادمین ۲۰تایی دارد → چیزهای مهم (گردش کار، تأییدها، تبادل داده، گزارش‌ها…) ته منو گم می‌شوند.
- **سه ناوبری موازی** وجود دارد: سایدبار، هاب‌های تکراری (`/workspace` مرکز عملیات، `/monitoring` مرکز پایش، `/admin` مرکز مدیریت، `Q_GROUPS` داخل `workspace.tsx`) و نوار تب موبایل. هر هاب یک منوی دوم ساخته است.
- **صفحات تکراری/هم‌پوشان** وجود دارند که کاربر را سردرگم می‌کنند (جدول §۴).
- **کشف‌پذیری ضعیف**: سوییچ «نمای ساده/کامل» در حالت ساده، هوش، گزارش، اسناد، تأییدها، تبادل داده و تنظیمات را کاملاً پنهان می‌کند؛ گردش کار اصلاً فقط در بخش «فقط مدیران» است.
- صفحاتی **فقط از راه URL** قابل دسترسی‌اند (هیچ لینکی در سایت ندارند): `admin/criteria`، `admin/custom-fields`، `admin/integrations`، `admin/notification-rules`، `admin/scoring`، `admin/tags`، `api-coverage`، `backend-coverage`، `authorization`، `workspace`، `notifications`، `data-management/quality`.

هدف پلن: **یک منو، یک سلسله‌مراتب، بدون از دست رفتن هیچ URL** — همهٔ بخش‌ها قابل استفاده و در دسترس، حداقل تکرار.

## ۳) یافته‌های کلیدی

### ۳٫۱ منوی فعلی (تصویر درد)

```
خانه            → پیشخوان
اشخاص و سازمان‌ها → سازمان‌ها، اشخاص                        ✅ خوب
روابط و شبکه     → روابط، شبکه، تعاملات، معرفی‌ها، هوش رابطه  ✅ خوب
جریان کار        → جلسات، تقویم، اقدامات، تعهدات، پروژه‌ها، فرصت‌ها ✅ خوب
هوش و بینش       → دستیار، بریف، توصیه‌ها، گزارش‌ها          ⚠ در «نمای ساده» پنهان
دانش و هماهنگی   → اسناد، نیازمندی‌ها، تأییدها، تبادل داده، تنظیمات، نشست‌ها ⚠ ته منو
────────────────────────────────────────────
مدیریت سیستم (فقط مدیران) — ۲۰ آیتم:
کاربران/مجوزها | امنیت/حاکمیت | داده/یکپارچه‌سازی/پایش
  ├ گردش کار ⚠ اینجا ته منو!
  ├ تحلیل محصول، سنجه‌ها، مشاهده‌پذیری، پایش، سلامت (۵ صفحهٔ هم‌موضوع)
  └ داده و کیفیت، کیفیت داده، تبادل داده، چرخهٔ حیات داده... (۴–۵ صفحهٔ هم‌موضوع)
```

- `SIMPLE_NAV` فقط ۴ گروه دارد؛ `SMART_NAV` و `BASE_NAV` کامل حذف می‌شوند → مستأجر/نقش ساده **دستیار هوشمند و گزارش‌ها را نمی‌بیند**.
- `/workflows` و `/approvals` نه یکجا و نه در جای درست‌اند (یکی «فقط مدیر»، دیگری ته منو).

### ۳٫۲ ناوبری‌های موازی (تکرار مهم‌تر از صفحه‌ها)

| صفحه | محتوا | وضعیت |
|---|---|---|
| `/` (پیشخوان) | وضعیت امروز شخصی | ✅ منو |
| `/dashboard` | همان پیشخوان | تکراری (redirect پنهان) |
| `/workspace` «مرکز عملیات» | هاب با ۷ گروه لینک (Q_GROUPS) | 🔴 یتیم — خودش یک منوی دوم است |
| `/monitoring` «مرکز پایش» | هاب سلامت/سنجه/صف | 🟡 در منو، ولی ۳ صفحهٔ هم‌موضوع کنارش |
| `/admin` «مرکز مدیریت» | هاب ۸ لینک | 🟡 فقط ۸ پیوند از ۱۴ صفحهٔ ادمین |
| نوار بالا | جستجو، ایجاد سریع، اعلان‌ها | ✅ خوب (اما `/notifications` صفحهٔ جدا هم دارد) |
| نوار موبایل | ۴ تب + «بیشتر» | ✅ خوب |

نتیجه: کاربر ۳–۴ بار همان لیست لینک‌ها را می‌بیند، و در هر بار **لیست متفاوتی** است.

### ۳٫۳ صفحات یتیم در بخش ادمین
صفحاتی که ساخته شده‌اند اما هیچ منو/لینکی ندارند (فقط URL مستقیم):
`admin/criteria`، `admin/custom-fields`، `admin/integrations` (تکراریِ `/integrations`)، `admin/notification-rules`، `admin/scoring`، `admin/tags` — یعنی قابلیت‌هایی (معیارها! برچسب‌ها! قواعد امتیازدهی!) که هیچ‌کس از داخل سامانه نمی‌تواند پیدا کند.

### ۳٫۴ صفحات توسعه/داخلی در نمای کاربر
- `/api-coverage` (رجیستری OpenAPI)، `/backend-coverage` (تطبیق سرور↔UI) → ابزار توسعه‌دهنده؛ باید به «راهنما/مستندات» بروند، نه منوی اصلی.

## ۵) معماری اطلاعات پیشنهادی — «۶ خانهٔ کاری + ۱ لایهٔ سیستم»

```
┌─────────────────────────────────────────────────────────────┐
│ نوار بالا: جستجو سراسری · ایجاد سریع · اعلان‌ها · محدوده    │
├─────────────────────────────────────────────────────────────┤
│ ۱) امروز           پیشخوان (ادغام‌شده با مرکز عملیات)         │
│ ۲) مخاطب‌ها        سازمان‌ها · اشخاص                          │
│ ۳) روابط           روابط · شبکه · تعاملات · معرفی‌ها ·        │
│                    هوش رابطه                                  │
│ ۴) کار و اجرا      تقویم/جلسات · اقدامات · تعهدات · پروژه‌ها · │
│                    فرصت‌ها · نیازمندی‌ها                       │
│ ۵) هوش             دستیار · بریف هفتگی · توصیه‌ها · گزارش‌ها  │
│ ۶) اتوماسیون و هماهنگی                                         │
│      گردش کار · تأییدها · اسناد · تبادل داده ·                │
│      تنظیمات من · نشست‌های من                                  │
├─────────────────────────────────────────────────────────────┤
│ سیستم (مدیر): ۴ تب = کاربران/مجوزها | امنیت/حاکمیت |          │
│                 داده/یکپارچه‌سازی | پایش و سلامت               │
└─────────────────────────────────────────────────────────────┘
```

قواعد:
1. **یک آیتم منو = یک مسئلهٔ کاربر**؛ مسئله‌های زیرمجموعه با **تب** داخل همان صفحه حل می‌شوند (تب‌ها قبلاً در سامانه استفاده می‌شوند و با موبایل سازگارند).
2. **حذف سوییچ «ساده/کامل»** → یک منوی واحد. نقش‌بندی با خودِ permission انجام می‌شود نه مخفی‌سازی دسته‌ها؛ به همهٔ نقش‌ها، همهٔ خانه‌هایی که برایشان مجاز است نشان داده شود.
3. **گردش کار/تأییدها از بخش ادمین خارج و به خانهٔ ۶ منتقل شوند** (قابل مشاهده برای همهٔ نقش‌های مجاز — دقیقاً همان کاری که «پایین منو» را آزاردهنده کرده).
4. URLهای قدیمی هرگز حذف نمی‌شوند؛ فقط **ریدایرکت (۳۰۱/کلاینتی)** به مقصد جدید.
5. اسکرول عمودی منو حذف؛ سایدبار همیشه کوتاه و قابل‌اسکن (حداکثر ~۱۴ آیتم در حالت عادی).

## ۶) نقشهٔ راه اجرا (۴ فاز)

### فاز A — منو و جای‌گیری (کم‌هزینه، بیشترین اثر) · ~۱–۲ روز
- بازنویسی `NAV_*` در `workspace.tsx` بر اساس §۵ (حذف سوییچ ساده/کامل، انتقال گردش کار/تأیید، گروه‌بندی جدید).
- یکپارچه‌سازی آیتم‌های موبایل (تب‌ها) با همان مدل.
- حذف آیتم‌های تکراری از منو (`/dashboard`، `/workspace`، `/knowledge`، `/admin/integrations`…) بدون حذف فایل‌ها.
- تکمیل «مرکز سیستم» (`/admin`) با لینک به **همهٔ** زیرصفحات (criteria/custom-fields/notification-rules/scoring/tags…).
- خروجی: کاربر در ۲ کلیک به هر بخش می‌رسد؛ ته منو هیچ چیز «مهم»ی نیست.

### فاز B — ادغام صفحات تکراری (با ریدایرکت) · ~۱–۲ روز
- ریدایرکت‌ها: `/dashboard → /`، `/workspace → /`، `/authorization → /admin/permissions`، `/admin/integrations → /integrations`، `/data-management/quality → /data-quality`، `/metrics → /monitoring`، `/observability → /monitoring`، `/health → /monitoring`، `/knowledge → /documents` (موجود).
- `api-coverage` و `backend-coverage` → بخش «مستندات فنی» داخل `/help` (منوی اصلی ندارند).
- هر فایل قدیمی فقط `export { default } from '...'` یا `redirect()` می‌شود؛ هیچ API/مسیری نمی‌شکند.

### فاز C — هاب‌های تب‌دار (یک مسئله = یک صفحه) · ~۲–۳ روز
- «اتوماسیون و هماهنگی»: `/workflows` + `/approvals` → تب‌دار (یا یک صفحهٔ مشترک با ۲ تب).
- «داده»: `/data-management` هاب با تب‌های `quality` / `import` / `master-data`؛ `/data-exchange` به «تبادل» همان‌جا.
- «امنیت و حاکمیت»: `/security` هاب تب‌دار (events / governance / privacy / lifecycle).
- «پایش و سلامت»: `/monitoring` هاب تب‌دار (santé / metrics / observability / health).
- هوش: `ai`/`recommendations`/`intelligence` — منو یک آیتم با تب، صفحات حفظ.
- `notifications` صفحه → «ترجیحات و تاریخچه» (کشوی بالا همان) — یا حذف از منو و لینک از کشو.

### فاز D — یکپارچگی UX و کیفیت · ~۱–۲ روز
- جستجوی سراسری، ایجاد سریع، اعلان‌ها: یک نسخه در نوار بالا (حذف ورودی‌های دوم).
- استانداردسازی سربرگ/فیلتر/جدول صفحات هم‌خانواده (الگوهای موجود `crud-workspace`/`operational-table`).
- بازبینی `pages-checklist.md` و `PLATFORM-GUIDE.md` مطابق IA جدید.

## ۸) معیار موفقیت

1. با نقش «دمو» (مالک) هر یک از ۸۲ مسیر در **حداکثر ۲ کلیک** از منو در دسترس است.
2. هیچ صفحهٔ `0 inbound` در بخش‌های ادمین وجود ندارد (همه از «مرکز سیستم» قابل دسترس).
3. در منو هیچ دو آیتمی به یک مسئلهٔ واحد اشاره نمی‌کنند.
4. «گردش کار/تأییدها» در منوی **غیر ادمین** نیز دیده می‌شود (برای نقش‌های مجاز).
5. بازگشت به هر URL قدیمی → همان مقصد جدید (بدون ۴۰۴).
6. روی موبایل: تب‌ها + «بیشتر» با منوی جدید هماهنگ‌اند.

## ۹) پیشنهاد شروع (اولین قدم پیشنهادی)

فاز A + بخشی از B را با هم اجرا کنیم: منوی جدید (۶ خانه + سیستم) + ریدایرکت‌های ساده + تکمیل هاب ادمین. این کار بدون ریسک داده‌ای است و بیشترین بهبود را در «قابل استفاده بودن» ایجاد می‌کند؛ فاز C را بعد از بازخورد شما روی منوی جدید انجام می‌دهیم.
