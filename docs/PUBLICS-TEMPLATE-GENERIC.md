# الگوی عمومیِ عموم‌ها — نسخهٔ بدون نامِ خاص

> **مبدأ:** استخراج‌شده از `PUBLICS_TEMPLATES.HOLDING` پس از عمومی‌سازی (حذف «پارس» و «۱۲»).  
> این الگو برای هر هلدینگِ چندبخشی قابل استفاده است؛ برای هر سازمان `missionTopic` و `sectors/subsidiaries`ِ خودش فصلِ پوشش را می‌سازد.

## کاتالوگ
- ۶ دسته: داخلی، نهادی و حاکمیتی، علمی/دانشگاهی، اقتصادی/سرمایه‌گذاری، رسانه‌ای/عمومی، اکوسیستم فناوری
- ۵ نوع پیوند: فعال‌کننده، کارکردی-ورودی، کارکردی-خروجی، هنجاری، پراکنده
- ۴ مرحله: غیرعموم، نهفته، آگاه، فعال
- ۴ موضع: بازیگر کلیدی، تأثیرگذار، حامی، ناظر

## قالب HOLDING (عمومی‌شده)
- **توضیح الگو:** «نقشهٔ شروع برای هلدینگ‌های چندبخشی؛ پوشش حوزه‌های کاری در هر ۶ دسته (قابل تنظیم)»
- **گروه‌های داخلی (نمونه):**
  - هیئت‌مدیره هلدینگ — فعال‌کننده / فعال / بازیگر کلیدی — «تصمیم‌گیرنده نهایی؛ روایت هسته ابتدا اینجا تثبیت می‌شود»
  - مدیرعامل و تیم اجرایی — فعال‌کننده / فعال / بازیگر کلیدی — «سخنگویان طبیعی پیام کلیدی سازمان»
  - مدیران‌عامل حوزه‌های کاری — فعال‌کننده / آگاه→فعال / بازیگر کلیدی — «بزرگ‌ترین ریسک پراکندگی پیام»
  - مدیران میانی هر حوزهٔ کاری — کارکردی-ورودی / نهفته→آگاه / تأثیرگذار
  - کارکنان عملیاتی حوزه‌های کاری — کارکردی-ورودی / نهفته / حامی — «بزرگ‌ترین جمعیت عموم داخلی»
  - ... (سایر گروه‌ها بدون عددِ ثابت؛ هر سازمان تعداد حوزه‌های خودش را در `structure.subsidiaries` ثبت می‌کند)

## شخصی‌سازی per-tenant
- `PUT /publics/self/:orgId` با `{companyType, missionTopic, structure: {sectors, subsidiaries, ownership}}`  
- `PUT /publics/groups/:orgId/:groupId` برای بازنویسیِ نام/یادداشت/کانال همان گروه فقط در همان سازمان  
- گروه‌های غیرضروری `active=false` می‌شوند و از `coverage` خارج می‌شوند؛ گروه‌های جدید `POST /publics/groups/:orgId` با `source=custom` ساخته می‌شوند.

> برای دیدنِ نمونهٔ کاملِ گروه‌ها، `apps/web-ux/scripts/mock-api.mjs` بخش `PUBLICS_TEMPLATE_LIST` را ببینید.
