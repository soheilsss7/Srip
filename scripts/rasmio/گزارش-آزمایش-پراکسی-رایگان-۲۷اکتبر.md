## اصلاحاتی که در جریان تست لازم شد

1. اولین اجرا واقعاً ۲۰ نامزد را امتحان کرد، اما انتشار اختصاصی خروجی به علت نادیده‌گرفته‌شدن فایل‌های out نیاز به اصلاح داشت. خروجی توسط گام بعدی workflow حفظ شد؛ آن اجرا workflow موفق محسوب نشده است. انتشار محدود با `git add -f` اصلاح شد و اجراهای بعدی موفق شدند.
2. ثبت HTTP و ریدایرکت نشان داد مسیر سادهٔ شرکت زنجیرهٔ 308 دارد: مسیر بدون slash، سپس مسیر slashدار، سپس direct، سپس direct/.
3. آزمون اولیه بدون دنبال‌کردن کامل این زنجیره، نمی‌توانست نتیجهٔ قطعی دربارهٔ نبود جزئیات بدهد. آزمایش به نشانی canonical عمومی `/company/<id>/direct/` تغییر کرد و پاسخ‌های 200 دارای جدول دریافت شد.
4. همین نشانی عمومیِ تأییدشده برای مسیر شرکت در ربات اصلی هم اعمال می‌شود تا زنجیرهٔ ریدایرکت حذف شود؛ این تغییر به‌تنهایی تضمین رفع محدودیت نیست.
5. چرخش ناهمزمان و تکرار پروفایل در نمونه محدود مهار شد؛ خروجی تکراریِ یک شناسه دوباره به‌عنوان رکورد جدید ذخیره نمی‌شود.

## محدودیت‌ها و وضعیت اتصال

**مسیر رایگان واقعاً استفاده شده، اما حالت آزمایشی و محدود است؛ اتصال سراسری و دائمی کل خزنده به پراکسی عمومی فعال نشده است.**

- حالت `public-proxy-probe`: کنترل اتصال و دریافت یک شرکت شناخته‌شده، بدون تغییر فایل اصلی شرکت.
- حالت `public-proxy-repair-sample`: انتخاب حداکثر دو شرکتِ فاقد فایل غیرخالی از فهرست ترمیم؛ ذخیرهٔ نمونهٔ معتبر و جایگزینی فقط فایل خالی/خراب در آخرین remote.
- هر اجرا حداکثر ۲۰ نامزد، همزمانی ۲، حداکثر ۴ درخواست شرکت شامل ریدایرکت و حداکثر دو خروجی ذخیره‌شده دارد. این سقفِ آزمایش است، نه ادعای تضمین چهار صفحه برای هر IP.
- حالت‌های آزمایش، جانشین خودکار نمی‌سازند و frontier/visited/گراف روابط را ویرایش نمی‌کنند. دو فایل پُرشده ممکن است تا بازخوانی عادی در فهرست ترمیم صف باقی بمانند؛ نباید کاهش خودکار remaining یا کشف روابط جدید را به این نمونه نسبت داد.
- خزش عادی شرکت/شخص/محصول متوقف نشده و مسیر عادی اشخاص به پراکسی منتقل نشده است. موفقیت اشخاص از این مسیر هنوز آزمایش نشده است.
- IP سرویس echo ممکن است با IP دیده‌شده در مقصد دیگر متفاوت باشد، خصوصاً پراکسی‌های دارای خروجی متغیر. نامزدهای 5.129.254.x در آزمایش واقعاً IP خروجی متفاوت از IP سرور پراکسی نشان دادند. تضمین IP تازه برای رسمیو ادعا نمی‌شود.
- نمونهٔ کنترل و دو نمونهٔ ترمیم، اثبات ظرفیت نامحدود، پایداری طولانی، همهٔ بخش‌های پروفایل یا سرعت ۹ شرکت در دقیقه نیستند.

## احتیاط‌های اعمال‌شده

- child processهای اتصال پراکسی فقط PATH، HOME موقت و LANG دارند؛ کلید GitHub و دیگر متغیرهای محرمانه به curl/Chromium آزمایش داده نمی‌شوند.
- کوکی حساب استفاده نمی‌شود؛ TLS و اعتبارسنجی گواهی خاموش نشده‌اند.
- مسیر مستقیمِ fallback برای curl وجود ندارد؛ پراکسی صریح و NO_PROXY خالی است.
- مقصد HTTPS به سرویس echo مشخص و همان شناسهٔ شرکتِ انتخاب‌شده محدود است؛ ریدایرکت به دامنهٔ دیگر یا مسیر ورود رد می‌شود.
- سرورهای خصوصی/رزروشده، نام میزبان دلخواه، credential داخل URL و پروتکل‌های نامجاز از فهرست نامزدها کنار گذاشته می‌شوند.
- Chromium صرفاً parser آفلاین HTML است؛ JavaScript صفحه غیرفعال و درخواست‌های صفحه مسدود می‌شوند.
- انتشار خروجی با index جدا و parent تازهٔ remote انجام می‌شود تا صف و دادهٔ همزمان ربات اصلی جایگزین نشود.
